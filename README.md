# Пианино с нуля — MVP

Платформа для самостоятельного обучения игре на пианино. Два независимых приложения в одном репозитории:

| Папка | Что это | Стек |
|---|---|---|
| `frontend/` | сайт (статика) | Vite + React + TypeScript + react-router |
| `backend/` | API: аккаунты, прогресс, серверный лимит Free | Node.js 22+, Express, PostgreSQL |

Деплоятся раздельно, у каждого свой `package.json`.

## Локальный запуск
```
cd backend  && npm install && npm run dev     # API на :3001
cd frontend && npm install && npm run dev     # сайт на :5173 (запросы /api проксируются на :3001)
```

## Frontend (статическое приложение)
- Директория проекта: `frontend`
- Установка: `npm ci --include=dev` · Сборка: `npm run build` · Публикуемая папка: `dist`
- Адрес бэкенда задаётся в файле **`frontend/public/config.js`** (сейчас `apiUrl: 'https://api.piano-lab.ru'`, без слеша) — это работает без переменных сборки. Запасной вариант: переменная сборки `VITE_API_URL`.
- Переменная сборки `VITE_SITE_URL` — адрес сайта для Open Graph (необязательна).
- Нужен SPA-fallback: любой путь должен отдавать `index.html`.
- `npm run build:preview` — автономный демо-файл `piano-preview.html` (без сервера).

## Backend (Node.js / Express)
- Директория проекта: `backend`
- Установка: `npm ci` · Сборка: `npm run build` (проверка типов) · Запуск: `npm start` · Health-check: `/api/me`
- Переменные окружения:

| Переменная | Назначение |
|---|---|
| `CORS_ORIGIN` | адрес(а) фронта через запятую, например `https://app.example.ru` |
| `TRUST_PROXY=1` | если сервер за прокси с HTTPS |
| `DATABASE_URL` | **обязательна в продакшене**: адрес PostgreSQL, `postgres://пользователь:пароль@хост:5432/база` |
| `DATABASE_SSL` | `require` или `no-verify`, если база требует SSL (`no-verify` — для самоподписанного сертификата) |
| `DB_DIR` | только для разработки: папка встроенной базы PGlite (без `DATABASE_URL`; в продакшене отключено, если нет `ALLOW_LOCAL_DB=1`) |
| `COOKIE_SAMESITE` | `lax` (по умолчанию) или `none` — см. ниже |
| `APP_TZ` | часовой пояс суток лимита (по умолчанию `Europe/Moscow`) |
| `PORT` | порт (по умолчанию 3001) |
| `ALLOW_DEV_PRO=1` | разрешить тестовое включение Pro (в продакшене не включать) |
| `FREE_LIMIT_SECONDS` | переопределить лимит Free (для тестов) |

**Cookie входа.** Если фронт и бэк — поддомены одного сайта (`app.example.ru` и `api.example.ru`), оставьте `lax`. Если это разные сайты, нужен `COOKIE_SAMESITE=none` и HTTPS на обоих, но Safari и часть браузеров блокируют такие сторонние cookie — используйте поддомены одного домена.

## Почта, уведомления, купоны

**Почта (SMTP, порт 465, SSL).** Письма: подтверждение почты при регистрации, сброс пароля («Забыли пароль?»), уведомление о смене пароля и удалении аккаунта, обращения в поддержку, напоминания и «композиция дня».

| Переменная | Назначение |
|---|---|
| `SMTP_HOST` | сервер исходящей почты, например `smtp.yandex.ru`, `smtp.mail.ru`, `smtp.timeweb.ru` |
| `SMTP_PORT` | `465` (по умолчанию; SSL) |
| `SMTP_USER` | логин ящика, например `noreply@ваш-домен.ru` |
| `SMTP_PASS` | пароль приложения для этого ящика |
| `MAIL_FROM` | адрес отправителя (по умолчанию `SMTP_USER`) |
| `SUPPORT_EMAIL` | куда приходят сообщения из формы «Поддержка» (по умолчанию `SMTP_USER`) |

При запуске в логе: `Почта (SMTP): включена (…)` или причина ошибки.

**Браузерные уведомления (Web Push).** Ключи VAPID создаются автоматически при первом запуске и хранятся в базе (таблица `kv`); при желании можно задать `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`. Напоминания и «композиция дня» отправляются раз в день во время, выбранное пользователем (по `APP_TZ`). На iPhone уведомления работают только у сайта, добавленного на экран «Домой» (iOS 16.4+).

**Купоны.** Создаются запросом в базу (интерфейса администратора нет):
```sql
INSERT INTO coupons (code, days, max_uses, expires_at) VALUES ('PIANO30', 30, 100, '2026-12-31T23:59:59Z');
-- days = 0 — Pro навсегда; max_uses — сколько раз всего можно активировать
```

## Оплата Pro (ЮKassa)

Pro на срок (месяц 30 дн. / год 365 дн.) или навсегда, без автопродления. При действующем Pro можно купить только тариф с большим сроком (месяц → год → навсегда); срочный тариф начинается с окончания текущего, «навсегда» — сразу. Остальное сервер отклоняет (409). Чек по 54-ФЗ формирует ЮKassa («Чеки от ЮKassa»).
Схема: `POST /api/billing/checkout` создаёт платёж в ЮKassa → покупатель оплачивает на странице ЮKassa → возвращается на `/payment/return` →
ЮKassa шлёт HTTP-уведомление на `POST /api/billing/yookassa`. Телу уведомления не доверяем: платёж перезапрашивается по API
и проверяется (id, сумма, валюта, номер заказа); продление идемпотентно. Если уведомление запаздывает, страница возврата сама сверяет заказ по API.

**Переменные бэкенда** (ключи — только в переменных окружения, не в репозитории):

| Переменная | Назначение |
|---|---|
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` | shopId и секретный ключ из ЛК ЮKassa (Интеграция → Ключи API) |
| `PRO_MONTH_PRICE`, `PRO_YEAR_PRICE`, `PRO_FOREVER_PRICE` | цены в рублях: месяц, год, навсегда (например `890`, `2990`, `5990`); без цены тариф не показывается |
| `YOOKASSA_VAT_CODE` | код НДС в чеке (по умолчанию `1` — без НДС; зависит от вашей системы налогообложения) |
| `YOOKASSA_TAX_SYSTEM` | код системы налогообложения, только если в магазине их несколько |
| `FRONTEND_URL` | адрес фронтенда для `return_url` (по умолчанию первый из `CORS_ORIGIN`) |
| `YOOKASSA_IP_CHECK=1` | принимать уведомления только с адресов ЮKassa (нужен верный `TRUST_PROXY`) |

**В личном кабинете ЮKassa:** Интеграция → HTTP-уведомления → адрес `https://<адрес бэкенда>/api/billing/yookassa`,
события `payment.succeeded`, `payment.canceled`, `refund.succeeded`. Адрес обязан быть на HTTPS.
Сначала проверьте на тестовом магазине (тестовые shopId/ключ), потом переключите на боевые и перезапустите бэкенд.

**Проверка развёртывания** (запускать на своём компьютере, где открыты оба сайта):

```bash
cd backend && npm run check-deploy -- https://api.piano-lab.ru https://piano-lab.ru --register
```

## Админ-кабинет
Скрытый адрес — в `frontend/src/adminUrl.ts` (в меню сайта ссылки нет). Адрес — только дополнительное сокрытие: данные отдаёт сервер (`/api/admin/*`) и только администратору.

| Переменная бэкенда | Назначение |
|---|---|
| `ADMIN_PASSWORD` | пароль входа в админ-кабинет (не короче 12 символов). Хранится только на сервере; сессия — 12 часов; не больше 5 попыток за 15 минут |
| `ADMIN_EMAILS` | (необязательно) email аккаунтов, которым админка открывается без пароля, если они вошли на сайт и почта **подтверждена** |
| `ANALYTICS_SALT` | (необязательно) секретная соль для хеша посетителей; без неё случайная соль создаётся один раз и хранится в базе |

Без входа `/api/admin/*` отвечает 404. Если не задан ни `ADMIN_PASSWORD`, ни `ADMIN_EMAILS`, админка выключена. Разделы: Dashboard (KPI, графики, воронка), Пользователи (поиск, фильтры, блокировка — заблокированный выходит со всех устройств и не может войти), Платежи (из таблицы `payments` ЮKassa: фильтры по периоду, статусу, тарифу, итог), Маркетинг.

## Маркетинговые ссылки (Instagram и др.)
`https://<сайт>/go/instagram` — переход записывается, и человек сразу попадает на главную. Поддерживаются `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` (например `/go/instagram?utm_source=instagram&utm_medium=reels&utm_campaign=launch`); в админке → «Маркетинг» статистика по ссылкам и по меткам, конструктор ссылки и кнопка «Копировать».
- Цепочка: переход → id визита в браузере на 30 дней → при регистрации связывается с аккаунтом (`users.mkt_click_id`) → при оплате сохраняется в платеже (`payments.mkt_click_id`). Конверсии считаются от уникальных посетителей.
- Хранится: ссылка, UTM, домен источника, язык, тип устройства / ОС / браузер, страна (только если её передаёт CDN, например заголовок `CF-IPCountry`), время. IP и User-Agent не сохраняются — только хеш посетителя с солью. Боты и headless-браузеры не засчитываются.
- Новая ссылка с отдельным адресом — добавить slug в `MARKETING_LINKS` (`backend/src/marketing.ts`).

## Ноты (PDF): как добавлять
Каталог нот — `backend/content/scores.json` (метаданные), сами файлы — `backend/content/scores/<id>.pdf`.
Папка **не раздаётся как статика**: PDF отдаёт только защищённый эндпоинт `GET /api/scores/:id/download`
(нужен вход и активный Pro; иначе 401/403). Страницы фронтенда менять не нужно — каталог приходит с сервера.

```
cd backend
npm run add-score -- --file ~/Downloads/minuet.pdf --id minuet-in-g --title "Менуэт соль мажор" \
  --composer "К. Петцольд" --difficulty beginner --genre "Классика" --description "..." [--songId ode-to-joy] [--pages 2]
```
Скрипт копирует PDF без изменений и добавляет/обновляет запись. `--songId` связывает ноты с песней (блок «Ноты для фортепиано» на странице песни).

## Обложки песен и нот
Векторные обложки в едином стиле лежат в `frontend/public/covers/songs/<id>.svg` и `frontend/public/covers/scores/<id>.svg`.
Генерируются скриптом (тема и мотив — в `THEMES` внутри скрипта; у песен с нотами рисуется линия их мелодии):
```bash
cd frontend && ../backend/node_modules/.bin/tsx scripts/make-covers.ts
```
Добавили песню или ноты — перезапустите скрипт. Своя картинка: укажите `coverUrl` у песни в `frontend/src/data/songs.ts`.

## Курс и уроки
Курс — 40 уроков в 8 этапах (по 5 уроков), уровни: Начальный → Базовый → Средний → Продвинутый.
- **Структура** (этапы → уроки) — одна: `STRUCTURE` в `frontend/src/data/course.ts`. Из неё вычисляются номер урока, этап, уровень, предыдущий урок и длительность; число уроков везде берётся из данных (`LESSONS.length`).
- **Контент** уроков — `frontend/src/data/lessons/*.ts` (`a`–`d`: уроки l1–l24, `e`–`f`: l25–l40). У урока: название, описание, цели, этапы с блоками (текст, схема клавиш, упражнение, тест, ритм, метроном, нотный стан, чек-лист), задания для самостоятельной практики (`practice`) и ожидаемый результат (`outcome`; для l1–l24 — в `EXTRAS` в `course.ts`).
- **id уроков постоянные** — на них завязан прогресс. Новый урок: новый id, контент в `lessons/*.ts`, место — в `STRUCTURE` и в `LESSON_ORDER` в `backend/src/content.ts`.
- Статусы уроков (заблокирован / доступен / начат / завершён) и прогресс X / N, % — `lessonStatus` и `courseProgress` в `frontend/src/lib.ts`.
- Кубки за уроки: 1, 5, 10, 20, 30 и весь курс (`backend/src/achievements.ts`).

Проверка контента: `cd frontend && ../backend/node_modules/.bin/tsx scripts/validate-lessons.ts` (диапазоны клавиш, длительность 30–40 мин, практика и результат у каждого урока, каждый урок ровно в одном этапе).
Видео в уроках необязательны (`videoUrl`).

## Общий контент
Бэкенду нужны id уроков, цепочки `prerequisites`, id песен, лимит и версия документов — они лежат в `backend/src/content.ts`. При изменении уроков, песен, лимита или `LEGAL_VERSION` во фронтенде запустите `cd backend && npm run check:sync` (нужен полный чекаут репозитория): он сообщит о рассинхроне.

## Что открыто на Free
- **Песни:** список `FREE_SONG_IDS` — в `frontend/src/data/config.ts` и `backend/src/content.ts` (должны совпадать, проверяет `npm run check:sync`). Остальные песни — Pro (сервер не даст отметить их выученными без Pro).
- **Ноты:** в `backend/content/scores.json` у бесплатных записей стоит `"free": true` — их можно открыть для просмотра. Остальные ноты сервер отдаёт только Pro. Скачивание PDF — всегда только Pro.
- **Прогресс:** основные цифры и прогресс по курсу — всем; график, история и подробная статистика — Pro.

## Лимит Free
Клиент отправляет секунды активности, сервер ограничивает их реально прошедшим временем между запросами аккаунта и считает сутки по `APP_TZ`. Очистка браузера, повторный вход и другое устройство лимит не сбрасывают.
